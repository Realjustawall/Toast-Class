# Offline operation

TOASTER targets a self-hosted server reachable over a LAN with public Internet disconnected. This is different from operating a multi-user classroom with no network at all. The installation must already contain its binaries, images, database, dependencies and any optional model/signature data. The application bundle now passes a targeted fresh-installation/scanner/conversion/HTTPS workflow in an internal namespace without Internet egress. Bare-OS provisioning, complete platform acceptance and physical-device/TURN-only certification remain pending. See OFFLINE_INSTALL.md.

## Current implemented asset boundary

- React UI, Manrope and Vazirmatn are built and served locally. There are no required remote font/CDN imports in current product source.
- `npm run dev` and `npm run build` run `scripts/prepare-offline-assets.mjs`. It generates `apps/web/public/intro/toaster-works.html` from the supplied root file. Build output includes it locally. Do not remove the source file from the build context.
- The supplied animation embeds Three.js and its geometry/font data. The source is preserved, including its MIT header. A generated loader bridge suppresses audio initialization, hides standalone playback/progress controls, starts silently and renders a static scene under reduced motion. Loading ends when server data actually resolves, without a forced 17.8-second delay.
- A sandboxed iframe (`allow-scripts`, no same-origin privilege) isolates the animation from account cookies/storage. Its CSP denies network connections and remote assets. The parent provides accessible readiness/error/retry/leave controls. WebGL failure does not prevent the parent loading status or classroom recovery.
- Existing media uses self-hosted LiveKit through TOASTER's authenticated signaling gateway. MySQL, filesystem storage and the isolated converter can run locally. Configure reachable LAN media addresses and local ICE/TURN; do not depend on public STUN for disconnected operation. TURN-only and physical-device disconnected operation have not yet been verified.

## Preparation versus runtime

The current developer setup still uses `npm ci`, image pulls and initial OS package installation. These need Internet access or a pre-populated mirror/cache. They are **not** a complete air-gapped installer. The implemented exporter packages seven cached images by immutable ID, checksums, public installation scripts and notice guidance. Docker-only bootstrap creates new secrets on the target and needs no host Node/npm. Build preparation may need Internet; target application configuration/load/start do not. OS/Docker packages, full source-obligation review and recovery automation remain pending. Never include generated installation secrets in a distributable.

Production HTTPS on a disconnected LAN needs an internal CA or a provisioned trusted certificate. Public ACME issuance/renewal cannot be required offline. Production antivirus must have a locally available signature database and an explicit offline update policy. AI/OAuth/email integrations must remain optional when their providers are unavailable.
