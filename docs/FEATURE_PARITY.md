# Feature parity and requirement traceability

Initial inventory, 2026-11-05. This matrix groups related subrequirements from the master brief; it is not an assertion of exhaustive individual acceptance-test coverage. All major subsystems are tracked. No phase is complete.

Statuses: NOT_STARTED, IN_PROGRESS, IMPLEMENTED, TESTED, VERIFIED, BLOCKED. TESTED means only the evidence in that row has run. VERIFIED requires the full defined acceptance procedure, including independent-device tests where relevant. No feature is currently VERIFIED.

Scope update: [SCOPE_UPDATES.md](SCOPE_UPDATES.md) supersedes the original payment requirements. Payments are excluded by explicit user instruction; free events/registration remain required. Offline runtime and the supplied TOASTER WORKS loader are required.

S = [Skyroom official overview](https://www.skyroom.online/). Unknown means unconfirmed in the reviewed official source, not absent from that product. Neither reference's performance claims are TOASTER benchmarks.

## Acceptance procedure

Foundation: run API security tests and browser registration?organization?classroom workflow; repeat against PostgreSQL. Media: two independent physical devices, publish audio/video/screens, inspect received tracks, then TURN-only/reconnect and denied permissions. Teaching: two authorized browser contexts synchronize durable content and reject unauthorized mutations. Recording: verify decodable output and playback authorization. LMS/events: transactional end-to-end workflows including negative authorization cases. Production: clean Ubuntu install, recovery drill, cross-browser accessibility audit and capacity tests with recorded hardware/codecs/network. None of the latter procedures has been completed.

## Teaching milestone update

Classroom sessions start/end transactionally. A unique active key prevents parallel active sessions in one classroom. Activity mutations lock the session row so ending a session serializes against poll/timer/hand changes. The event gateway is authenticated, Origin-checked, read-only and periodically reauthorizes sockets. Updates contain invalidations only; every data refresh rechecks permissions. Reconnection uses capped exponential delay. Gateway broadcasts are process-local: Redis coordination remains required before running multiple API replicas.
