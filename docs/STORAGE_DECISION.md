# Storage and presentation implementation decision

Status: filesystem and S3 adapters, private file API, library UI and basic synchronized presentations implemented. SeaweedFS 4.52 passes the real operations contract; advanced presentation tools and production hardening remain pending. Reviewed 2026-11-06. This does not mark either full subsystem complete. See [files](FILES.md) and [presentations](PRESENTATIONS.md).

The storage boundary will use standard S3 operations with a replaceable provider, keeping object keys private and binding metadata to an organization and, where applicable, an authorized classroom. Local development may use a filesystem adapter; production replicas need shared object storage. The API must authorize access before serving or signing content. An object-key prefix alone is not tenant authorization.

The upstream [MinIO community repository](https://github.com/minio/minio) is now archived. TOASTER will retain S3 compatibility rather than depend on that project's continued releases. [Garage](https://garagehq.deuxfleurs.fr/documentation/quick-start/) is the initial self-hosted provider to evaluate. Its [documented S3 compatibility](https://garagehq.deuxfleurs.fr/documentation/reference-manual/s3-compatibility/) must be verified against the operations we actually use. Single-node installation requires explicit backup/restore procedures; [multi-node deployment](https://garagehq.deuxfleurs.fr/documentation/cookbook/real-world/) is optional for the initial VPS path. No provider compatibility claim is made before contract tests.

Untrusted uploads will be quarantined with size, type, quota and ownership validation before release. Malware scanning must expose unavailable/failed states; an unavailable scanner must not produce a clean result. Conversion will run in a separate resource-limited, network-isolated process/container with no application credentials. Original files and conversion metadata must persist independently of derived output.

The document pipeline uses [LibreOffice's documented conversion parameters and isolated profile](https://help.libreoffice.org/latest/en-GB/text/shared/guide/start_parameters.html?DbPAR=BASIC&System=WIN), producing PDF and Poppler-rendered PNG pages inside restricted containers. Headless mode is not itself the sandbox. Durable claims, timeout/failure reporting, authorized retry and persisted teacher-controlled page state are implemented. See PRESENTATIONS.md for exact tested formats and pending features.

The filesystem upload/download, tenant guards, quota races, scan state machine, folders/copy/delete and real S3 operations pass tests. PDF/TXT/DOCX conversion and two-browser synchronized pages also pass. Deployed scanner contracts, advanced annotations, annotated exports and slide-to-board import remain part of the original requirement scope.

The actual Garage 2.5.0 experiment failed conditional-create: a second put succeeded despite `If-None-Match: *`. A separate HTTP fixture confirms the adapter sends that header. Garage is rejected for the current immutable-write contract. SeaweedFS 4.52 subsequently passed the same contract plus concurrent creation, with exactly one writer winning. See [storage tests](STORAGE_TESTS.md). No racy HEAD-before-PUT substitute was introduced. Native-server compatibility does not certify container packaging or cluster durability.
