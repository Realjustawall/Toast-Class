# دسته‌های گفت‌وگوی کلاس

پیش‌فرض هر کلاس فقط «عمومی» است. مدیر کلاس از دکمهٔ **+** کنار دسته‌ها، پنجرهٔ «مدیریت دسته‌های گفتگو» را باز می‌کند و دستهٔ دلخواه می‌سازد یا حذف می‌کند. نقش‌های مالک و مدرس، مطابق اختیار مدیریتی فعلی کلاس، این دسترسی را دارند؛ دانشجو اجازهٔ تغییر دسته‌ها ندارد و این محدودیت در API هم اعمال می‌شود.

- «عمومی» ثابت است و حداکثر ۱۲ دستهٔ اختصاصی با نام حداکثر ۶۰ نویسه می‌توان ساخت. نام خالی، تکراری و نویسهٔ کنترلی پذیرفته نمی‌شود.
- پیام‌ها به دستهٔ انتخاب‌شده تعلق دارند. علامت سؤال، پیام را به دستهٔ دیگری منتقل نمی‌کند. تب ثابت «پرسش‌ها» حذف شده است.
- تغییر دسته‌ها برای اعضای کلاس از طریق اتصال زنده همگام می‌شود. نام‌های طولانی سه‌نقطه می‌گیرند و تعداد زیاد دسته‌ها داخل نوار قابل پیمایش است. انتخاب با کلیدهای جهت، Home و End نیز انجام می‌شود.
- حذف دسته، پیام‌هایش را در همان تراکنش به «عمومی» منتقل می‌کند. کاربران حاضر در دستهٔ حذف‌شده به عمومی برمی‌گردند. حذف دسته، سابقهٔ پیام را پاک نمی‌کند.
- پیش‌نویس‌ها برای هر دسته جدا ذخیره می‌شوند. پیش‌نویس قبلی عمومی با همان کلید ذخیره‌سازی سازگار است. کنترل ویرایش/حذف پیام و قفل چت حفظ شده‌اند.

## دیتابیس و API

مهاجرت MySQL در `packages/database/mysql/012_chat_categories.sql` و معادل PostgreSQL در `packages/database/migrations/019_chat_categories.sql` است. جدول `chat_categories` به کلاس و سازنده متصل است. ستون اختیاری `messages.category_id` و شاخص کلاس/دسته/زمان اضافه شده‌اند؛ پیام‌های قبلی با مقدار `NULL` در عمومی باقی می‌مانند.

| مسیر زیر `/api/v1/classrooms/:id`          | رفتار                                                |
| ------------------------------------------ | ---------------------------------------------------- |
| `GET /chat-categories`                     | فهرست دسته‌های اختصاصی؛ عمومی در رابط ثابت است       |
| `POST /chat-categories` با `{name}`        | ساخت دسته توسط مدیر                                  |
| `POST /chat-categories/:categoryId/delete` | انتقال پیام‌ها و حذف دسته توسط مدیر                  |
| `GET /messages?categoryId=public`          | ۱۰۰ پیام آخر عمومی                                   |
| `GET /messages?categoryId=<uuid>`          | ۱۰۰ پیام آخر دسته در همان کلاس                       |
| `POST /messages` با `{body, categoryId}`   | ارسال به دسته؛ نبودن یا `null` بودن شناسه یعنی عمومی |

مسیر قدیمی `GET /messages` بدون پارامتر برای سازگاری، ۱۰۰ پیام آخر همهٔ دسته‌ها را برمی‌گرداند. دسته‌ها بخش‌بندی گفتگو برای اعضای همان کلاس‌اند و پیام خصوصی نیستند. شناسهٔ دستهٔ متعلق به کلاس دیگر برای ارسال پذیرفته نمی‌شود. ساخت هم‌زمان دسته‌ها با قفل رکورد کلاس محدود می‌شود؛ ساخت و حذف در گزارش مدیریتی ثبت می‌شوند.

مهاجرت روی پیش‌نمایش بومی http://localhost:5174 اعمال و حفظ پنج پیام قبلی با مقایسهٔ داده‌ها بررسی شد. اطلاعات حساب و کلاس تست حفظ شده‌اند. برای محیط دیگری باید مهاجرت متناسب با دیتابیس را پیش از راه‌اندازی نسخهٔ جدید اجرا کرد. نصب وابستگی جدیدی لازم نبود؛ فایل‌ها، کش و خروجی‌های این کار روی E قرار دارند.

## نتیجهٔ بررسی

[شواهد ماشینی](CHAT_CATEGORIES_VERIFICATION_2026-11-09.json) مسیر گزارش اجرای نهایی را مشخص می‌کند.

- مجموعهٔ کامل با MySQL واقعی: **۹۴ تست موفق از ۹۷، صفر شکست، سه تست وابسته به محیط خارجی اجرا نشده**.
- سناریوی تازهٔ دسته‌ها و تست قبلی مدیریت پیام با آداپتور پیش‌فرض نیز موفق شدند. تست تازه پس از اصلاح نوع دادهٔ ابزار تست دوباره روی MySQL اجرا شد و موفق بود.
- سه سناریوی مرورگری موفق: مدیریت دسته‌ها با دو کاربر، چیدمان فشرده و حالت لمسی در چهار طرح، و دسترسی/قالب‌بندی/چیدمان چهار کلاس.
- سناریوی تازه، پیش‌فرض تک‌دسته‌ای، منع تغییر توسط دانشجو، همگام‌سازی زنده، جداسازی پیام و پیش‌نویس، ماندگاری پس از بارگذاری دوباره، حذف با حفظ تاریخچه، سقف دسته‌ها، صفحهٔ فارسی ۳۲۰ پیکسلی و انتخاب با صفحه‌کلید را بررسی می‌کند.
- TypeScript و ساخت وب و سرور موفق بودند. هشدار قبلی اندازهٔ بسته‌های وب باقی است.
- همان حساب واقعی تست، فقط عمومی را نمایش داد و پنجرهٔ مدیریت در موبایل قابل استفاده بود؛ برای این بررسی دسته یا پیام آزمایشی به کلاس کاربر اضافه نشد.
